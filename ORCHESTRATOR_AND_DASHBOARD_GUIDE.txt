THE ORCHESTRATOR (ai_singularity_orchestrator.py)
==================================================

The orchestrator is an autonomous management system with 8 subsystems:

1. HEALTH MONITOR
   - Tracks: Bot status, win rate, P&L, drawdown, signal count, API latency
   - Updates: Every 60 seconds
   - Purpose: Know system health at all times

2. PERFORMANCE ANALYZER
   - Tracks: Win rates (7-day, 30-day), Sharpe ratio, profit factor
   - Updates: Every 60 seconds
   - Purpose: Understand trading performance trends

3. RISK OVERSEER
   - Tracks: Current drawdown, daily loss %, position concentration
   - Enforces: Max 10% drawdown, 5% daily loss, 2% per trade
   - Purpose: Capital preservation

4. SCALING ENGINE
   - Monitors: Win rate and Sharpe ratio
   - Decides: SCALE_UP if WR>75% AND Sharpe>2.0
   - Decides: SCALE_DOWN if WR<65% OR Sharpe<0.5
   - Decides: MAINTAIN otherwise
   - Purpose: Grow profitably when edge is strong, reduce when weak

5. ANOMALY DETECTOR
   - Detects: High API latency (>500ms), no signals, high error rate (>5/day)
   - Updates: Every 60 seconds
   - Purpose: Find problems before they become critical

6. SELF-HEALER
   - Fixes: Reduce API calls for latency, check algorithm for missing signals
   - Fixes: Pause for diagnostics if error rate spikes
   - Purpose: Automatically resolve issues

7. DECISION ENGINE
   - Makes: High-level autonomous decisions
   - Purpose: Strategic project-level choices
   - Status: Framework ready, decision logic extensible

8. COMPREHENSIVE REPORTER
   - Generates: Executive summaries, performance reports
   - Updates: Every 4 hours during market hours
   - Purpose: Big picture analysis

THE DATA FLOW
=============

Every 60 seconds, this happens:

1. Orchestrator collects metrics from bot
   - win_rate, sharpe_ratio, current_drawdown, daily_pnl, etc.

2. Stores metrics in history (1440 points = 24 hours)

3. Makes scaling decision
   - Compares metrics to thresholds

4. Detects anomalies
   - Checks for latency, missing signals, errors

5. Attempts self-healing if anomalies found

6. Writes current state to JSON file (ai_metrics_latest.json)

7. Dashboard reads JSON and updates visually

8. You see the results in browser instantly


INTERPRETING THE SCALING DECISIONS
==================================

SCALE_UP means:
  - Win rate > 75% AND Sharpe > 2.0
  - Edge is strong and consistent
  - System will increase position sizes
  - More capital allocated to trading
  - Higher expected profit

SCALE_DOWN means:
  - Win rate < 65% OR Sharpe < 0.5
  - Edge has weakened
  - System will reduce position sizes
  - Less capital exposed to risk
  - Preserves capital for recovery

MAINTAIN means:
  - Win rate between 65-75%
  - Sharpe ratio between 0.5-2.0
  - System operating normally
  - No changes needed


WHAT IF SOMETHING GOES WRONG?
==============================

Dashboard shows red indicators:
  1. Check ai_logs/ folder for detailed error messages
  2. Look at anomaly section for what was detected
  3. Check if self-healer took action
  4. If still red after 2 minutes, may need manual intervention

Bot stops generating signals:
  1. Dashboard shows 0 daily signals
  2. Anomaly detector will flag "no_signals_generated"
  3. Self-healer will verify algorithm parameters
  4. May need to check:
     - Alpaca connection working
     - Market data fresh
     - Algorithm parameters correct

High API latency (>500ms):
  1. Anomaly detector will flag "high_api_latency"
  2. Self-healer will reduce API call frequency
  3. Dashboard shows latency in market connection card
  4. Temporary; usually resolves on its own

Drawdown approaching limit:
  1. Risk overseer monitors constantly
  2. If drawdown > 10%: Bot automatically pauses
  3. Dashboard shows drawdown progress bar
  4. System will resume when conditions improve

HOW THE ORCHESTRATOR ACTUALLY MAKES SCALING DECISIONS
======================================================

Every 60 seconds:

1. Look at last 7 days of performance data
   - Calculate average win rate
   - Calculate average Sharpe ratio

2. Compare to thresholds:
   - If avg_wr > 75% AND avg_sharpe > 2.0:
       Decision = SCALE_UP (add more assets or larger positions)
   - Else if avg_wr < 65% OR avg_sharpe < 0.5:
       Decision = SCALE_DOWN (reduce exposure)
   - Else:
       Decision = MAINTAIN (no changes)

3. Log the decision with reasoning

4. If SCALE_UP or SCALE_DOWN:
   - Attempt to execute
   - Log results
   - Update dashboard

5. Store in history for next check
